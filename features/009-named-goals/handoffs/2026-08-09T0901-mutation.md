# atdd-mutate — handoff summary

## What I did

Swept both modules `plan.md` opts in to whole — 263 single-node mutants — through
a two-phase ladder that ends in the full acceptance stream, then read every
survivor back as product behaviour. I wrote none of this code and no tests to
kill anything.

## Artifacts produced

The JSON reports listed in the frontmatter, under the gitignored `.build/`, and
this handoff. No source file was changed.

## The numbers

```
domain/rules.py     128 mutants   124 killed    4 survived   96.9%   STRONG
services/metas.py   135 mutants    76 killed   59 survived   56.3%   WEAK
                    263            200         63            76.0%
```

Adjusted for the mutants that cannot change behaviour: rules 124/126 = **98.4%**,
metas 76/128 = **59.4%**. Both verdicts hold.

## How it was run, and what the ladder proved

Phase A, cheapest rung first:

```
rules.py   uv run pytest -q -x tests/domain
           uv run pytest -q -x ../features/003-…/generated ../features/009-…/generated
metas.py   uv run pytest -q -x tests/api/test_metas.py tests/services/test_month_aggregate.py
           uv run pytest -q -x ../features/009-named-goals/.build/generated
```

Phase B put every Phase A survivor through the two expensive rungs — all eight
generated acceptance dirs (472 tests) and the whole backend suite (1012 tests).

```
rules.py    8 survivors entering Phase B   ->  4 killed,  4 left
metas.py   59 survivors entering Phase B   ->  0 killed, 59 left
```

**That second line is the most useful number in this report.** Feature 008's
lesson was that the unit stream alone over-reports survivors; here the opposite
holds for `metas.py`. Nothing in the other 1449 tests touches this module in a
way the 22-test API file and 009's own acceptance suite do not already. More
tests of the kinds already present will not move this score.

Runtime was ~63 minutes wall clock. To fit that, `rules.py` and three of the four
`metas.py` Phase B chunks ran in detached `git worktree` copies with their own
`uv` venvs and their own regenerated acceptance tests, so no two sweeps could see
each other's mutated source. Isolation was verified by importing `quaestor` in
each worktree and confirming `__file__` pointed inside it. All four worktrees are
removed.

## The green gate earned its keep

Four of the six sweeps refused to start:

```
RuntimeError: stage 2 is 'fail' with no mutation applied, so every mutant
would count as killed and the score would be meaningless: uv run pytest -q -x
```

The worktrees had no `backend/quaestor.db` schema, so
`tests/test_scheduler.py::TestRunOnce::test_run_once_success` failed on
`sqlite3.OperationalError: no such table: recurring_item` — an environment
failure with nothing to do with mutation. `alembic upgrade head` in each worktree
fixed it and the baseline came back `1012 passed`. Without the gate those four
chunks would have reported a perfect score for a stage that tested nothing.

`rules.py` is genuinely well tested: 124 of 128 mutants died, two survivors are
provable no-ops, and the two that remain are the same guard's return value.

`services/metas.py` is not, and the shape of the failure is specific. There is
**no `backend/tests/services/test_metas.py`**. Every sibling service has one —
`test_funds.py`, `test_reports.py`, `test_transactions.py`,
`test_month_aggregate.py`, `test_planned.py`, `test_recurring.py`,
`test_rollover.py` — and the module that folds every meta figure forward has
none. Its only unit pressure arrives through 22 HTTP round-trips in
`tests/api/test_metas.py`, which by design assert that the wire reaches the rule
rather than what the rule computes. The 112 acceptance tests then bind at
`services.metas` but exercise the happy paths the scenarios describe.

The result is that arithmetic which is *displayed* is untested (progress,
ordering, the archive's order — asserted in vitest against fixtures), and writes
which are *guarded* are untested (what `close_meta` and `restore_meta` set once
past the refusal, what `_amend` selects before it overwrites).
