**Findings (no behavior defects):**
1. **Hidden env prerequisite in the acceptance runner** —
   `./run-acceptance-tests.sh` neither sets nor documents SESSION_SECRET;
   without it exported the AC-13 parity scenario fails (create_app
   requires >=32 bytes), which is easily misread as a code regression.
   Recommend: runner sets a test-only default or fails fast with a clear
   message.
2. **Dead kwargs in a test** — backend/tests/services/test_planned.py:326
   (`_planned_transfer`) still passes `fx_rate=Decimal("1"), to_base=amount`
   to `Transaction(...)`; SQLModel silently ignores unknown kwargs. Stale,
   should be deleted.
3. **Acceptance-handler docstring drift** (refiner already flagged) —
   acceptance/handlers/fx_read_time.py:51-53 still speaks in the future
   tense ("The feature's migration will be a later revision"). Cosmetic;
   left untouched to keep the verified pipeline byte-identical during
   verification.
4. **Documented naming remnants** (deliberate, per refine handoff):
   REST `ToPayOut.total_base` field name, MCP `set_fx_rate`/`get_fx_rate`
   tool names (ADR-0020 frozen), frontend `fxRate` zod primitive.
