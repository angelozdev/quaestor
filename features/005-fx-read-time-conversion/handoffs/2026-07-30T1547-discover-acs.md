# discover-acs — handoff summary

## What I did

Discovered feature 005's acceptance criteria in reverse-engineer mode
(ADR-0031 + discuss handoff as source material), interviewed only genuine
gaps (batched), and wrote `acs.md` with 14 ACs. A mid-discovery design
question from the user ("why is the TRM a table?") was resolved with
industry research (Beancount price DB, Firefly III dated rates): the user
chose a **single scalar TRM value** — coherent with the already-chosen
"everything at current rate" semantic, under which dated history is never
read. ADR-0031 was amended in place (explicit Amended note; the ADR was
uncommitted, so no published decision is contradicted) and `feature.md`
scope updated.

## Gap decisions (user-confirmed)

1. TRM = single scalar value; dated `fx_rate` table dropped in the
   migration; daily job overwrites; last write wins.
2. Reads always require the TRM — even pure-COP surfaces fail loud when it
   was never set (stricter option chosen over fail-only-on-conversion).
3. Cross-currency transfer dialog shows the implied rate (received ÷ sent)
   as live reference info; no ratio validation.
4. Migration = clean drop with `just backup` immediately before; no
   archive table for old frozen values.
