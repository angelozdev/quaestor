# discuss — handoff summary

## What I did

Explored replacing the frozen-snapshot FX design (`to_base`/`fx_rate` frozen
at registration) after the user rejected snapshots during prime-context of
002-transactions-crud. Researched industry practice (Beancount/Ledger
report-time conversion, Firefly III primary-currency model, IAS 21).
Outcome: **promote**.

## Key decisions (user-confirmed)

1. **No per-transaction rate override** — the `fx_rate` table is the only
   source of truth; the per-tx `fx_rate` field and dialog input are removed.
2. **Everything at current rate** — one semantic: most recent TRM converts
   all surfaces, including past expenses. The IAS 21 hybrid (tx-date rate
   for flows, current rate for stocks) was recommended and explicitly
   rejected; the user accepts that closed months' totals move with the TRM.
3. **Cross-currency transfers in scope** — same-currency validation removed;
   two explicit physical amounts (sent/received), each leg stores its own
   amount/currency, no rate stored (implicit = ratio). Matches Firefly III
   two-amount transfers / Beancount `@` annotation.
4. Fail-loud `MissingRate` at read time; registration no longer requires a
   rate. No silent rate-1 fallback.
5. Out of scope: functional `Settings.base_currency` (COP stays hardcoded).
