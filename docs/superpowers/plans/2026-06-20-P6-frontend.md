# P6 — Frontend (v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the minimal v1 frontend — login, a Dashboard (safe-to-spend + "to-pay" widget with one-click mark-paid) and a Monthly Report — as a thin Next.js client of the P1 HTTP API, after first exposing the already-built `reports`/`budgets`/`goals` services as thin REST routers so the contract the UI needs actually exists.

**Architecture:** Two parts. **Part A (backend, 3 tasks):** the `reports`, `budgets` and `goals` *services* exist and are tested, but P1 never published them over HTTP. We add three thin routers (pure adapters, zero business logic — same shape as `accounts.py`/`planned.py`) plus their Pydantic `*Out` response schemas, and register them in the app factory. **Part B (frontend, 11 tasks):** a Next.js App-Router SPA. Auth uses a **BFF proxy**: a catch-all Next route handler at `app/api/[...path]/route.ts` forwards every `/api/*` browser call to the backend and pipes the backend's httpOnly `quaestor_session` cookie both ways. Pages are Client Components that call the same-origin proxy through a typed `lib/api.ts` via TanStack Query; the only Server Component is the `(app)` layout, which guards by calling the backend `/auth/me` server-side. The browser never learns the backend URL and there is no CORS in the browser.

**Tech Stack:** Backend: Python 3.12, FastAPI, SQLModel, Pydantic v2, `pytest` (via `uv run pytest`). Frontend: Next.js (App Router) 15, TypeScript, Tailwind, shadcn/ui, TanStack Query, `date-fns`, `sonner` (toasts). Node 20+.

## Global Constraints

These apply to every task. Values are copied verbatim from the P6 spec (`docs/superpowers/specs/2026-06-16-P6-frontend-design.md`) and verified against the backend as built.

- **Zero business logic in the client.** The frontend orchestrates fetch + render + formatting only. Net, budget %, goal ETA, total-to-pay, safe-to-spend — all arrive already computed from the API. The client never recomputes them and never does business arithmetic on amounts.
- **Money is integer cents, always positive in the data.** Every amount in the API is an `int` in cents with `SCALE=100` for **both** COP and USD (verified in `backend/src/quaestor/domain/money.py`). The frontend divides by 100 only for display. Sign and color are derived from the transaction `type`, never from the amount.
- **Display formatting (`formatCents`, es-CO):** COP → `"$ "` + integer pesos grouped with dots, **no decimals** (e.g. `123456700` → `"$ 1.234.567"`). USD → `"US$ "` + 2 decimals (e.g. `1234` → `"US$ 12.34"`). This is the **frontend** format; it intentionally differs from the backend markdown's `"$12,345.67 COP"`. The `/reports` page therefore renders the report's **structured data** with `formatCents`, not the raw `markdown` field (which stays available but unused in v1).
- **The API lives under `/api`.** Every backend route is mounted with `prefix="/api"` (e.g. `/api/auth/login`, `/api/planned/to-pay`). The frontend's `lib/api.ts` prepends `/api` and calls the **same-origin** BFF proxy, which re-targets `${API_URL}/api/...`.
- **Auth = backend session cookie, brokered by the BFF.** `POST /api/auth/login {password}` makes the backend set an httpOnly signed `quaestor_session` cookie. The proxy forwards that `Set-Cookie` to the browser and forwards the browser's `Cookie` back to the backend on every call. The `APP_TOKEN` bearer is for server-to-server (MCP) only and must never reach the client. The spec's earlier "Next route handler mediates APP_TOKEN" wording is superseded by this BFF design (see *Decisions to record* below).
- **Thin routers only (Part A).** The new routers contain no logic beyond calling the existing service and returning its result; all rules stay in `services/`. This is P1-contract growth, not new behaviour.
- **v1 scope is exactly three screens:** `/login`, `/` (Dashboard), `/reports`. Everything else (transactions, to-pay dedicated view, recurring, budgets, goals, masters, import, settings) is **backlog**, operated through the agent (MCP) in the meantime. Do not build backlog screens.
- **No frontend test framework in v1** (spec: "manual testing; component tests later"). Frontend verification per task = `npx tsc --noEmit` passing **and** a concrete manual smoke check against the running app. `lib/money.ts` additionally gets a runnable Node check. Backend tasks keep full TDD with `pytest`.
- **i18n:** UI copy is Spanish (es-CO), matching the user's language. Code identifiers stay in English (ADR-0001).
- **Backend test command:** `uv run pytest` from `backend/` (config: `pythonpath=["src"]`, `testpaths=["tests"]`; package root `quaestor`).
- **Manual-test prerequisites (Part B):** run the backend in one terminal —
  `cd backend && APP_PASSWORD=dev-password APP_TOKEN=dev-token SESSION_SECRET=dev-secret uv run uvicorn quaestor.api:app --reload --port 8000` —
  and the frontend in another — `cd frontend && npm run dev` (port 3000). Log in with `dev-password`.

## Decisions to record (ADR — per `CLAUDE.md`, do after the plan is approved)

Two architecturally-significant choices deviate from the spec's literal wording and should be captured with the `adr` skill before/while executing:
1. **BFF proxy + backend session cookie** for auth, replacing the spec's "Next route handler mediates `APP_TOKEN`" sketch. Rationale: the backend already issues an httpOnly `quaestor_session` cookie with CORS credentials; the BFF hides the API URL and removes browser CORS entirely.
2. **P6 grows the P1 contract** by exposing the existing `reports`/`budgets`/`goals` services as thin routers (they were built in P4/P5 as services only). Rationale: v1's "done" criteria require these endpoints and the adapters carry no logic.

### Task B2: BFF proxy route handler

**Files:**
- Create: `frontend/app/api/[...path]/route.ts`

**Interfaces:**
- Produces: a catch-all proxy. Any browser request to `/api/<path>?<query>` is forwarded to `${API_URL}/api/<path>?<query>` with the `Cookie` and `Content-Type` headers passed through; the upstream status, body, `Content-Type` and **all** `Set-Cookie` headers are returned to the browser. Handles GET/POST/PATCH/DELETE.

- [ ] **Step 1: Write the proxy**

Create `frontend/app/api/[...path]/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";

const API_URL = process.env.API_URL ?? "http://localhost:8000";

async function proxy(req: NextRequest, path: string[]) {
  const target = `${API_URL}/api/${path.join("/")}${req.nextUrl.search}`;

  const headers: Record<string, string> = {};
  const contentType = req.headers.get("content-type");
  if (contentType) headers["content-type"] = contentType;
  const cookie = req.headers.get("cookie");
  if (cookie) headers["cookie"] = cookie;

  const hasBody = req.method !== "GET" && req.method !== "HEAD";
  const body = hasBody ? await req.text() : undefined;

  const upstream = await fetch(target, {
    method: req.method,
    headers,
    body,
    redirect: "manual",
    cache: "no-store",
  });

  const res = new NextResponse(await upstream.text(), { status: upstream.status });
  const upstreamContentType = upstream.headers.get("content-type");
  if (upstreamContentType) res.headers.set("content-type", upstreamContentType);
  for (const c of upstream.headers.getSetCookie()) res.headers.append("set-cookie", c);
  return res;
}

type Ctx = { params: Promise<{ path: string[] }> };

export async function GET(req: NextRequest, ctx: Ctx) {
  return proxy(req, (await ctx.params).path);
}
export async function POST(req: NextRequest, ctx: Ctx) {
  return proxy(req, (await ctx.params).path);
```

```ts
/**
 * Format an integer amount of cents for display (es-CO).
 * Amounts arrive as positive integer cents (SCALE=100 for both COP and USD).
 * COP: "$ 1.234.567" (no decimals). USD: "US$ 12.34" (2 decimals).
 * This is display-only; the client never does business arithmetic on amounts.
 */
export function formatCents(cents: number, currency: string): string {
  if (currency === "USD") {
    const major = cents / 100;
    const formatted = new Intl.NumberFormat("en-US", {
      minimumFractionDigits: 2,
      maximumFractionDigits: 2,
    }).format(major);
    return `US$ ${formatted}`;
  }
  const pesos = Math.round(cents / 100);
  const formatted = new Intl.NumberFormat("es-CO", { maximumFractionDigits: 0 }).format(pesos);
  return `$ ${formatted}`;
}
```

```ts
async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`/api${path}`, {
    ...init,
    credentials: "include",
    headers: { "Content-Type": "application/json", ...(init?.headers ?? {}) },
  });

    const message = (data && data.detail) || `Request failed (${res.status})`;
    throw new ApiError(res.status, code, message);
  }
  return data as T;
```

```tsx
      qc.invalidateQueries({ queryKey: ["reports"] });
```
